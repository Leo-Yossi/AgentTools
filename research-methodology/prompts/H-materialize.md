# 提示词 H：从框架续跑，产出具体数据集/论文条目（concrete materialization）

> **用途**：当你已经有一份"调研框架/任务书"（如 `topics/` 下领域样例的阶段 0~1.5 产物，或一份只列了方向、关键词、检索锚点的草稿），本提示词驱动 agent 把"待填充"的占位与检索锚点，落实为**带真实链接、可验证的具体条目**。
>
> **两层产出模型（先认清，避免误会）**
> - **脚本层（一键可得）**：`assets/build_query.py` 把关键词变成各平台**检索链接**（搜索入口），不是已筛选资源。它是起点。
> - **agent 层（需执行）**：具体数据集/论文条目（名称、规模、许可、真实链接、相关性）由 agent 执行阶段 2/3/5 时，联网检索 → 抓取候选页 → 验证存在/相关/许可 → 输出结构化条目得出。这是需要判断与抓取的任务，脚本无法替代。**本提示词就是 agent 层的标准动作。**

---

## 输入
- 一份框架文件（含：研究对象、核心概念组 A/B/C、检索式、以及"数据集/论文/产业"各节的占位或检索锚点）
- 用户指定的侧重（如"偏数据集/论文"）

## 执行步骤（每步都输出中间结果，别闷头一次性给终稿）

### 1. 数据集具象化（对应 SOP 阶段 5）
对框架中"数据集"节的每个槽位，用 `WebSearch` 检索该资源是否真实存在、获取方式与许可，输出结构化条目：

```
| 名称 | 内容/规模 | 许可 | 获取方式 | 与本方向的可迁移性 | 链接 |
```
- ✅ = 公开可下载
- ⚠️ = 学术自建 / 不公开，但方法、标注规范、规模可复用（注明"需联系作者/自行采集"）
- ❓ = 许可不明（社区上传等，需用户自行确认）

### 2. 论文具象化（对应 SOP 阶段 2/3）
对"论文"节的每个槽位，用 `WebSearch` + `WebFetch` 定位真实论文（**优先 DOI / 官方页 / 出版社页**，次之可靠聚合页），输出：

```
| 标题 | 作者 / 年份 / venue | 核心结论 | 与本方向相关性 | 链接 |
```
按类型打标：🔬 检测类 / 🛡️ 效果评估类 / 📡 监测系统类 / 📚 综述类。

### 3. 链接校验
对写出的所有外链跑：
```bash
python assets/check_links.py <本次产出的文件>.md
```
403/404 多数为 WAF 拦截，用浏览器 UA 复测，**勿直接判失效、勿据此删链接**。

### 4. 诚实性约束（红线）
- 未实际验证的资源**不写"已确认"**，用"待实跑验证 / 检索锚点"标注。
- **不臆造** DOI、作者、年份、卷期、指标数字；数字须来自检索结果或原文。
- 标注清楚哪些是"公开可复用"、哪些是"方法可复用但数据不公开"——这是本方向（电力场景）最常踩的坑。

### 5. 回填
把具象化结果写回框架对应节，占位符与锚点**全部替换**；若框架是模板（含 `<方向>` 占位符），先让用户确认课题再填。

## 输出
1. 一份"具体资源版"框架：数据集 / 论文章节为**真实条目 + 链接**。
2. 一张"仍待补充 / 需授权"清单（哪些资源不公开、哪些许可待确认、哪些需用户自己采集）。

## 触发语（用户任意一句即可让 agent 续跑）
- "继续，把数据集和论文写成具体条目带链接"
- "跑 phases 2/3/5" / "materialize" / "续跑"
- 直接把框架文件丢给 agent 说"按 H 续跑"
