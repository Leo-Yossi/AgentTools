# 01 · 数据集调研（通用科研全领域）

> 目标：回答"**训练/验证/测试的数据从哪来**"。
> 组织方式：综合聚合平台 → 社区/代码托管 → 国内平台（国家级 / 大厂 / 高校）→ 学科专题库 → 从论文挖数据 → 检索技巧 → 许可合规。

---

## 0. 三条找数据的路径（先选路，再动手）

| 路径 | 适用场景 | 起点 |
| --- | --- | --- |
| **A. 聚合搜索** | 只知道关键词，不确定有没有现成数据 | Google Dataset Search、re3data、DataCite |
| **B. 顺论文找** | 已有参考文献，想复现或对齐基线 | Papers with Code、论文 Dataset 章节、data journal |
| **C. 垂直库直取** | 已明确学科（如遥感、基因组、社科统计） | 本文第四节「学科专题库」 |

> 经验：**B 路径命中率最高**。绝大多数公开数据集是从论文里长出来的，先找到该方向 3～5 篇代表性论文，再看它们用了什么数据，比漫无目的搜平台高效得多。

## 2. 代码托管与开源社区里的数据集

> 很多数据集以"仓库 + 下载脚本"形式存在，不进任何数据平台。

| 名称 | 入口 | 说明 |
| --- | --- | --- |
| **GitHub Topic: dataset** | <https://github.com/topics/dataset> | 直接按 topic 检索，配合 `language:`/`stars:` 过滤 |
| **Awesome 系列清单** | <https://github.com/topics/awesome-datasets> | 各领域维护者整理的 curated list，质量高于随机搜索 |
| **GitHub 代码搜索** | `filename:download.sh dataset`、`path:**/data/README.md` | 直接从代码里挖数据下载链接 |
| **Gitee** 🇨🇳 | <https://gitee.com> | 国内镜像，访问快 |
| **ModelScope 魔搭数据集** 🇨🇳 | <https://www.modelscope.cn/datasets> | 阿里达摩院，中文数据集覆盖好，国内下载快 |
| **Hugging Face 镜像 hf-mirror** 🇨🇳 | <https://hf-mirror.com> | 国内 HF 加速镜像 |
| **启智 OpenI（鹏城实验室）** 🇨🇳 | <https://openi.org.cn> | 含数据集、模型、代码的国产开源社区 |
| **和鲸社区 ModelWhale** 🇨🇳 | <https://www.heywhale.com> | 数据科学社区，含数据集与 Notebook 环境 |
| **DataFountain** 🇨🇳 | <https://www.datafountain.cn/datasets> | CCF 大数据与计算智能大赛官方，赛题数据集质量较高 |

**实操技巧**：在 GitHub 用 `awesome-<领域>-datasets` 作为关键词搜索，几乎每个成熟方向都有人整理过清单（如 `awesome-speech-datasets`、`awesome-medical-datasets`）。

### 5.1 直接渠道

| 渠道 | 入口 | 说明 |
| --- | --- | --- |
| **Papers with Code** | <https://paperswithcode.com/datasets> | 论文 ↔ 数据集 ↔ 排行榜三者打通，按 task 直接看主流数据集 |
| **arXiv 搜索** | `site:arxiv.org "dataset" "<方向>" benchmark` | 新数据集往往先在 arXiv 发布 |
| **论文补充材料（Supplementary）** | 期刊页面 / Figshare / Zenodo / GitHub | 数据常以附件形式托管 |
| **Google Scholar 反查** | 搜数据集名 → 看谁引用了它 | 判断数据集是否被社区认可 |

### 5.2 专门发表数据集的期刊（Data Journal）

> 这类期刊的论文本身就是"数据集说明书"，是高质量数据源的富矿。

| 期刊 | 入口 | 说明 |
| --- | --- | --- |
| **Scientific Data（Nature 子刊）** | <https://www.nature.com/sdata> | 全学科，数据论文标杆，质量与元数据规范度最高 |
| **Data in Brief（Elsevier）** | <https://www.sciencedirect.com/journal/data-in-brief> | 短文数据集描述 |
| **Earth System Science Data** | <https://essd.copernicus.org> | 地学 |
| **Biodiversity Data Journal** | <https://bdj.pensoft.net> | 生物多样性 |
| **Journal of Open Source Software（JOSS）** | <https://joss.theoj.org> | 数据+工具配套 |
| **中国科学·数据** 🇨🇳 | <http://www.sciencedb.cn>（关联 ScienceDB） | 国内数据论文 |

### 5.3 检索式模板

```
# 找某方向的数据集论文
site:arxiv.org <方向关键词> ("dataset" OR "benchmark" OR "corpus")
site:nature.com/sdata <方向关键词>
<方向关键词> dataset OR corpus OR benchmark filetype:pdf

# 判断某个数据集是否被主流采用
Google Scholar: "<数据集名>" → 按引用量排序
```

## 6. 数据集评估清单（下载前必查）

拿到一个候选数据集，逐项打勾：

- [ ] **规模**：样本量、时长、存储量是否够用？
- [ ] **许可**：是否允许研究 / 商用 / 再分发？（见第 7 节）
- [ ] **质量**：是否有标注说明？标注一致性（如 Kappa 系数）如何？有无已知错误清单？
- [ ] **划分**：是否有标准 train/val/test 划分？能否与已有 SOTA 公平对比？
- [ ] **活跃度**：社区是否还在用？最后一次更新是什么时候？
- [ ] **获取成本**：下载是否稳定？国内是否可直连？是否需要申请审批？
- [ ] **合规**：是否含个人信息、人脸、医疗数据？跨境传输是否合规？
- [ ] **可复现**：是否有配套 baseline 代码与指标？

## 7. 数据许可合规速查（⚠️ 高风险环节）

| 许可类型 | 典型代表 | 可否商用 | 关键限制 |
| --- | --- | --- | --- |
| **CC0 / Public Domain** | 政府开放数据部分 | ✅ | 无限制，最省心 |
| **CC BY** | 多数学术论文数据 | ✅ | 必须署名 |
| **CC BY-SA** | 部分社区数据 | ✅ | 衍生作品需同样协议（传染性） |
| **CC BY-NC** | 很多研究数据集 | ❌ | **禁止商用**，企业项目常见雷区 |
| **CC BY-ND** | 少量 | ✅ | 禁止演绎/修改 |
| **自定义研究用途（Research-only）** | ImageNet、部分竞赛数据 | ❌ | 仅学术用途，且常禁止再分发 |
| **平台协议** | Kaggle/天池竞赛数据 | 视赛题 | 竞赛数据常禁止赛后商用，务必看 rules |
| **GDPR / 个人信息保护** | 含人脸、医疗、用户行为的数据 | 个案 | 中国《个人信息保护法》、欧盟 GDPR 双重约束 |

**判断顺序**：先看平台标注的 License → 再去仓库找 `LICENSE` 文件 → 都没有则默认"仅研究用途、禁止再分发"，联系作者确认。

## 8. 检索技巧小结

1. **关键词组合**：`方向 + (dataset | corpus | benchmark | database)`，再加 `open` / `free` 提高开放命中率。
2. **用 DOI 反查**：论文里数据集若带 DOI，直接在 DataCite/Zenodo 搜索，可拿到最权威版本。
3. **HF 高级过滤**：`https://huggingface.co/datasets?license=cc-by-4.0&sort=downloads` 可按许可和热度排序。
4. **国内加速**：HF 用 `hf-mirror.com`；GitHub release 用镜像站；大文件优先看是否有云厂商镜像（AWS Open Data /阿里云）。
5. **批量发现**：DataCite / Zenodo / OpenML 均有开放 API，适合写脚本按学科批量拉取元数据做汇总。
