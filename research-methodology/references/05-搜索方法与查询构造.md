# 05 · 搜索方法与查询构造（一段话 → 关键词 → 检索式）

> 目标：把"我脑子里大概想做什么"变成"能在前面几份数据源里直接跑的检索式"。
> 核心链路：**自然语言想法 → 意图解析 → 概念拆解 → 术语对齐 → 检索式构造 → 多源路由 → 迭代修正**

---

## 0. 为什么需要这一步

调研失败的绝大多数情况，不是"找不到"，而是**第一步就搜错了**：

| 常见症状 | 真实原因 |
| --- | --- |
| 搜出来几千条，全是噪音 | 用了口语词，没做术语对齐，命中了字面匹配 |
| 搜出来个位数，明显不对 | 用了过窄的学术黑话，或漏了同义词 |
| 搜出来的都不是这个方向 | 概念歧义（如"模型"指 ML 模型还是数学模型） |
| 换了平台结果差不多 | 没有按意图做**多源路由**，在错误的库里深挖 |

**关键认知**：你说的话和学术数据库里的词，中间隔着一整层术语体系。这一步就是把这层翻译做扎实。

---

## 1. 四步转化流程

```
① 意图解析   ──► 从一段话里抽出 7 个结构化要素
      │
② 概念拆解   ──► 每个要素列 3~5 个同义/上下位/邻近词（中英双语）
      │
③ 术语对齐   ──► 口语词 → 学术术语；中文 → 英文；缩写 → 全称
      │
④ 检索式构造 ──► 按目标数据源的语法拼装布尔表达式
      │
⑤ 多源路由   ──► 不同意图走不同数据源（见第 5 节）
      │
⑥ 迭代修正   ──► 看首轮结果，按信号调整（见第 8 节）
```

---

## 2. 第一步：意图解析（把一段话拆成 7 个要素）

拿到一段自然语言，先不做任何搜索，而是填这张表：

| 要素 | 问自己的问题 | 例："我想让医院CT自动判断肺结节良恶性，小医院也能跑" |
| --- | --- | --- |
| **研究对象** | 核心实体是什么？ | 肺结节（pulmonary nodule / lung nodule） |
| **任务动作** | 要做什么？分类/检测/生成/预测/优化？ | 良恶性分类、风险分层 |
| **应用场景** | 在哪用？什么数据模态？ | CT 影像、放射科、基层医院 |
| **方法路线** | 有没有技术倾向？（没有就留空） | 深度学习、轻量模型 |
| **约束条件** | 算力/数据/成本/语言/时间限制？ | 算力受限、数据稀缺、需中文/国内数据 |
| **期望产出** | 要论文？数据集？代码？可落地方案？ | 数据集 + 轻量基线模型 + 评测指标 |
| **排除项** | 明确不要什么？ | 不要纯综述、不要非医学场景 |

> **要点**：约束条件最容易被忽略，但它往往决定了检索的成败（"数据稀缺"直接指向 few-shot / 自监督 / 迁移学习这条线）。

**给 AI 的解析提示词（模板 A）**

```
下面是我的一段想法，请帮我做意图解析，不要直接给答案，只做结构化拆解：

"""
<粘贴你的原始想法>
"""

请输出：
1. 7 要素表（研究对象/任务动作/应用场景/方法路线/约束条件/期望产出/排除项）
2. 你认为我话里有歧义的地方，列出 2-3 种可能的理解并说明差异
3. 你认为我隐含提到但没说出口的 2-3 个相关概念
4. 判断这个需求更偏"学术研究"还是"工程落地"，说明理由
```

## 3. 第二步：从概念到关键词（四层扩展）

每个核心概念都要扩展出四层词，这是召回率的保证：

| 层级 | 说明 | 例（概念 = 肺结节） |
| --- | --- | --- |
| **核心词** | 最直白的叫法 | 肺结节、pulmonary nodule |
| **同义词** | 完全等价的其他叫法 | 肺小结节、lung nodule、pulmonary lesion |
| **上下位词** | 上位（更泛）/ 下位（更具体） | 上位：肺部疾病、医学影像；下位：磨玻璃结节 GGN、实性结节 |
| **邻近词** | 常一起出现的相关概念 | 肺癌筛查、LIDC-IDRI、LUNA16、CAD 计算机辅助诊断 |

### 3.1 中英术语对齐（最关键的翻译层）

中文口语表达和英文检索词经常不是字面翻译关系，这是召回率损失的头号原因：

| 中文口语/常用说法 | 英文检索词（学术库实际在用） |
| --- | --- |
| 人工智能 / AI | machine learning, deep learning, neural network |
| 让机器看懂图片 | image classification, object detection, semantic segmentation |
| 自动写文章 | text generation, NLG, language model |
| 小样本 / 数据少 | few-shot learning, low-resource, data-efficient, self-supervised |
| 模型跑得快 / 省算力 | efficient inference, model compression, knowledge distillation, quantization, edge deployment |
| 让模型更懂人话 | instruction tuning, alignment, RLHF |
| 大模型 | large language model, LLM, foundation model |
| 防止数据泄露 | differential privacy, federated learning, privacy-preserving |
| 让结果可解释 | explainable AI, XAI, interpretability |
| 数据不够造一点 | data augmentation, synthetic data, generative model |
| 多学科交叉 | interdisciplinary, cross-domain |

> **实操**：不确定某个中文说法对应什么英文术语时，最可靠的办法是**反查** —— 先搜中文找到 1~2 篇相关中文论文，看它们的英文关键词（Keywords）字段，直接抄。

### 3.2 隐含概念补全（AI 的经验价值在这里）

用户说出口的往往只是冰山一角。基于领域经验补全：

| 用户说 | 应该补上的隐含概念 |
| --- | --- |
| "数据不好找" | few-shot, self-supervised pretraining, transfer learning, data augmentation, 公开数据集清单 |
| "要在小设备上跑" | model compression, quantization, distillation, edge inference, latency, FLOPs |
| "要能解释为什么" | explainability, attention visualization, SHAP, Grad-CAM |
| "要实时" | real-time, streaming, latency, throughput, online inference |
| "要合规" | privacy-preserving, federated learning, differential privacy, 数据脱敏 |
| "中文场景" | Chinese corpus, CLUE, 千言 LUGE, 中文分词, 国内开放数据集 |

## 4. 第三步：查询改写与扩展技术

### 4.1 基础布尔与字段限定

```
# 标准结构：概念间 AND，概念内 OR
(A1 OR A2 OR A3) AND (B1 OR B2) AND (C1 OR C2) NOT (D1)

# 字段限定（各库语法不同，见 02-论文调研 §6）
ti:"..."      标题
abs:"..."     摘要
kw:"..."      关键词
au:"..."      作者
```

### 4.2 五种扩展技术

| 技术 | 做法 | 什么时候用 |
| --- | --- | --- |
| **同义扩展** | 每个概念列 3~5 个同义词 OR 起来 | 默认必做 |
| **上下位扩展** | 泛化（提召回）或具体化（提精度） | 结果太少→泛化；太多→具体化 |
| **截词/通配** | `comput*` 命中 computer/computing/computation | 支持通配符的库（WoS、PubMed、EBSCO） |
| **邻近算符** | `NEAR/3`、`ADJ` 限定词间距离 | 短语在不同库分词不一致时 |
| **引文滚雪球** | 用 1 篇种子论文的前后引文替代关键词检索 | 已找到 1 篇高度相关论文后（见 04-SOP 阶段 4） |

### 4.3 LLM 时代的三种新打法 ⭐

| 打法 | 说明 | 适用 |
| --- | --- | --- |
| **Multi-Query 重写** | 让 AI 把同一意图改写成 5~8 个不同表述的检索式，分别搜后合并去重 | 召回不足、术语不确定时 |
| **语义/向量检索** | 用 embedding 相似度而非字面匹配（Semantic Scholar、OpenAlex、[Elicit](https://elicit.com)、[Consensus](https://consensus.app) 等，直接喂自然语言长句） | 概念抽象、字面词想不起来时 |
| **假设答案反推** | 让 AI 先生成"理想中的论文标题/数据集名称"，再用它去搜 | 完全陌生领域冷启动 |

```
# Multi-Query 提示词
把下面这个检索意图改写成 8 个不同的英文检索式，要求：
- 分别侧重不同的术语体系（学术术语 / 工程术语 / 同义词 / 上下位词）
- 2 个用严格 AND 提高精度，3 个放宽提高召回，3 个换个角度（如从任务名、数据集名、评测指标切入）
意图：<...>
```

### 4.4 精度与召回的调节旋钮

| 想达成的效果 | 操作 |
| --- | --- |
| 结果太多 → 提精度 | 增加 AND 概念；用 `ti:` 限定标题；加时间过滤；加排除词 NOT |
| 结果太少 → 提召回 | 减少 AND 概念；概念内加同义词；用 `abs:` 放开到摘要；去掉时间限制 |
| 结果不对 → 换角度 | 换一个概念作为主检索词；用数据集名/方法名反查；改用引文滚雪球 |

## 5. 第四步：多源路由（按意图选数据源）

**核心原则**：不同意图应该在不同类型的源里搜，在错误的库里优化检索式是白费力气。

| 你的意图 | 优先走哪些源 | 检索重点 |
| --- | --- | --- |
| 想知道"最新做到哪了" | arXiv、bioRxiv、ChinaXiv、HF Papers、GitHub Trending（见 02 §1、§7） | 近 2 年，按时间排序 |
| 想知道"什么被认可了" | 顶会顶刊、DBLP、WoS/Scopus（见 02 §5） | 按被引/来源过滤 |
| 想找"能跑的数据" | Google Dataset Search、HF、Kaggle、PWC（见 01 §1） | 按任务名 + 许可过滤 |
| 想找"评测基线/SOTA" | Papers with Code（见 01 §1.3、02 §5.4） | 按 task 检索，看榜单 |
| 想找中文/国内场景 | CNKI、万方、ChinaXiv、天池、AI Studio、OpenDataLab（见 01 §3、02 §2.3） | 中文检索式 |
| 想找"落没落地" | 展会、竞赛榜单、专利、招投标（见 03） | 公司名/产品名/专利号 |
| 想找实现代码 | GitHub、PWC、DBLP 关联仓库 | 仓库 topic + stars |
| 想找某团队的全部工作 | DBLP、Google Scholar 作者页、实验室主页 | 作者名精确匹配 |

**一次完整调研至少交叉 3 类源**：预印本（最新）+ 顶会顶刊（被认可）+ 数据集平台（可复现）。

## 7. 端到端案例（完整演示）

### 用户原始输入

> "我想看看有没有办法让医院里的 CT 影像自动判断肺结节是良性还是恶性，最好是能用小医院也跑得动的模型，数据不好找，要中文的或者国内医院的数据。"

### Step 1 · 意图解析

| 要素 | 提取结果 |
| --- | --- |
| 研究对象 | 肺结节（pulmonary/lung nodule） |
| 任务动作 | 良恶性分类、恶性风险预测 |
| 应用场景 | CT 影像、放射科、基层医院 |
| 方法路线 | 深度学习影像分类（未指定，留开放） |
| 约束条件 | 算力受限（轻量模型）、数据稀缺、需中文/国内数据 |
| 期望产出 | 可用数据集 + 轻量基线模型 + 评测指标 |
| 排除项 | 纯综述、非医学影像场景 |

### Step 2 · 关键词表

| 概念组 | 核心词 | 同义词 | 上下位/邻近 |
| --- | --- | --- | --- |
| **A 对象** | pulmonary nodule / 肺结节 | lung nodule, pulmonary lesion, 肺小结节 | 上位：lung cancer screening；下位：GGN 磨玻璃结节、solid nodule |
| **B 任务** | benign-malignant classification / 良恶性分类 | malignancy prediction, risk stratification, nodule characterization | CAD 计算机辅助诊断, lung cancer diagnosis |
| **C 约束-数据少** | few-shot learning / 小样本 | self-supervised, transfer learning, data-efficient, low-resource | data augmentation, synthetic data |
| **D 约束-轻量化** | lightweight model / 轻量模型 | efficient network, model compression, knowledge distillation, quantization, edge inference | MobileNet, ShuffleNet, pruning |
| **E 场景** | CT / computed tomography | chest CT, thoracic CT | LIDC-IDRI, LUNA16, NLST |

> 隐含补上的概念：**C（数据少）和 D（轻量化）用户其实只说了"小医院跑得动"和"数据不好找"，必须翻译成学术术语才搜得到。**

### Step 3 · 生成的检索式

```sql
-- arXiv（近 3 年，CS.CV + EESS.IV）
(abs:"lung nodule" OR abs:"pulmonary nodule") AND (abs:"malignancy" OR abs:"benign")
AND (abs:"lightweight" OR abs:"efficient" OR abs:"compression" OR abs:"distillation")
AND cat:cs.CV

-- Google Scholar
("pulmonary nodule" OR "lung nodule") AND ("malignancy classification" OR "benign malignant")
AND ("lightweight" OR "model compression") -review after:2022

-- PubMed（MeSH）
(("Solitary Pulmonary Nodule"[Mesh]) AND ("Diagnosis"[Mesh] OR "classification"))
AND ("Deep Learning"[Mesh] OR "Artificial Intelligence"[Mesh])

-- CNKI 知网
SU=('肺结节'+'肺小结节'+'孤立性肺结节') AND SU=('良恶性'+'恶性风险'+'良恶性鉴别')
AND (FT='深度学习' OR FT='人工智能')
-- 再叠加：SU=('轻量'+'模型压缩'+'轻量化') 做收敛

-- HuggingFace Datasets 检索词
lung nodule / pulmonary nodule CT / chest CT nodule / LIDC-IDRI

-- GitHub
topic:medical-imaging nodule stars:>50
"lung nodule" classification in:name,description
```

### Step 4 · 数据源路由

| 优先级 | 源 | 找什么 |
| --- | --- | --- |
| 1 | **Papers with Code** | 该任务有没有榜单、SOTA 是什么、用哪个数据集 |
| 2 | **LIDC-IDRI / LUNA16** | 学术界标准公开数据集（英文，量大） |
| 3 | **天池 / DataFountain** | 中文/国内的肺结节赛题数据（真实业务数据） |
| 4 | **PubMed + arXiv** | 学术方法与最新进展 |
| 5 | **CNKI** | 国内医院的实际研究与中文报告 |
| 6 | **中国医疗设备展会/CMEF** | 落没落地、有没有成熟产品（见 03 §1.2） |

### Step 5 · 首轮反馈与修正

**假设首轮在 arXiv 只搜到 3 篇** → 信号：过严。修正策略：
- 去掉 D 组（轻量化）约束，先确认"肺结节良恶性分类"这个主方向有多少工作
- 再单独搜 D 组 + 医学影像（不限肺结节），看轻量化方法在医学影像的通用做法
- 两条线结果做交集

**假设在 Google Scholar 搜到 5000 条** → 信号：过宽。修正策略：
- 用 `intitle:` 限定标题
- 加 `after:2022`
- 排除 `-review -survey`

## 8. 迭代闭环：搜索 → 看结果 → 修正

| 首轮信号 | 诊断 | 修正动作 |
| --- | --- | --- |
| 命中 < 10 条 | 过严 / 术语过窄 / 源选错 | 减少 AND 概念；加同义词；换更通用的上位词；换数据源 |
| 命中 > 1000 条 | 过宽 | 加 AND 概念；限定标题字段；加时间/语言/学科过滤 |
| 相关率 < 20% | 概念歧义 | 换主检索概念；加排除词；用邻近算符 |
| 全是老论文 | 领域已转向或术语已更新 | 查新术语（看近 2 年论文的 Keywords）；改用引文滚雪球 |
| 全是中文/全是英文 | 语言偏 | 补另一种语言的检索；中英双语分别搜后再合并 |
| 找到 1 篇完美的 | 别再关键词搜了 | 立刻转**引文滚雪球**（Research Rabbit / Litmaps，见 04-SOP 阶段 4） |

> **效率心法**：一旦找到 1 篇高度相关的论文，**立刻停止关键词检索，转到引文网络**。关键词检索的边际收益会断崖式下降，而引文网络此时命中率最高。

## 10. 自动化：批量生成各平台检索链接

关键词定下来后，手敲各平台 URL 很烦。用配套脚本一键生成：

```bash
python assets/build_query.py "肺结节|pulmonary nodule|lung nodule" "良恶性|malignancy|benign" "轻量|lightweight|compression"
```

- 用 **空格**分隔不同概念（概念之间 AND）
- 用 **`|`** 分隔同义词（概念内部 OR）
- 输出一张表：平台 / 检索式 / 可直接点开的 URL

```bash
# 只输出论文类平台
python assets/build_query.py "A|a1|a2" "B|b1" --only papers

# 输出 Markdown 表格，方便粘贴进调研记录
python assets/build_query.py "A|a1" "B|b1" --md
```

## 11. 常见坑

| 坑 | 表现 | 解法 |
| --- | --- | --- |
| **字面翻译** | 把"让机器看懂图片"直译成 let machine see pictures | 必须做术语对齐（见 3.1），或反查中文论文的英文关键词 |
| **概念歧义** | "模型" "框架" "平台" 这类多义词 | 加限定概念 AND 掉歧义，或用字段限定 |
| **缩写黑洞** | NLP（自然语言处理 vs 神经语言学编程） | 首次搜用全称，确认后可用缩写 |
| **一次搜到底** | 花 2 小时优化一个检索式 | 首轮粗搜 → 找到种子 → 转引文滚雪球（收益更高） |
| **只用英文** | 中文场景漏掉国内研究 | 中英双语分别检索，人工合并 |
| **忽略数据源差异** | 在 arXiv 找临床试验 | 按第 5 节做多源路由 |
| **不记录检索式** | 一周后想不起来怎么搜的 | 用第 12 节的记录模板，每次必填 |
